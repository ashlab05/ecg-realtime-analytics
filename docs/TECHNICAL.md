# Technical Documentation — ECG Real-Time Arrhythmia Analytics

**Project:** Deep Learning–Based Framework for Real-Time ECG Arrhythmia
Classification in Big Data Environments
**Dataset:** MIT-BIH Arrhythmia Database (feature-level export:
109,449 beats, 2 leads × 16 features = 32 features per beat)

---

The transport is pluggable behind `api/services/broker.py`:
`MESSAGE_BROKER=kafka` (default; Kafka topics + Spark) or
`MESSAGE_BROKER=redis` (Redis Streams + Python worker — see
[docs/REDIS_STREAMS.md](REDIS_STREAMS.md), experimental).

A dependency-free **demo mode** collapses the whole backend into one
process: `python3 demo/server.py` serves the built dashboard and runs
inference in-process with an in-memory store (no broker, no database).

## 2. Data & Features

Each heartbeat is described by 16 features per lead (Lead II + Lead V,
32 total, order fixed by `ecg_core/features.py`):

- **Rhythm:** pre-RR, post-RR intervals
- **Wave amplitudes:** P, Q, R, S, T peak amplitudes
- **Intervals:** QRS, PQ, QT, ST durations
- **Morphology:** 5 QRS-morphology samples (qrs_morph_0..4)

Classes (AAMI-style grouping, `ecg_core/labels.py`):

| Code | Class | Dataset count |
|---|---|---|
| N | Normal | 90,083 |
| SVEB | Supraventricular ectopic | 2,779 |
| VEB | Ventricular ectopic | 7,009 |
| F | Fusion | 803 |
| Q | Unknown | 15 |

Class imbalance ≈ 96.4% N — this drives the anomaly-detection framing.

## 3. Two-Stage Inference Pipeline (production)

**Stage 1 — anomaly gate (autoencoder).** Trained on *normal beats
only*; a beat is flagged anomalous when its scaled-feature
reconstruction error exceeds a threshold calibrated at the 95th
percentile of normal reconstruction errors
(**threshold = 0.059017**). Architecture: 32 → 128 → 64 → 16 → 64 →
128 → 32 (dense, linear output, MSE loss, Adam 1e-3, 50 epochs,
batch 256).

**Stage 2 — abnormal classifier (XGBoost).** Only anomalous beats are
routed here; a 4-class model distinguishes SVEB / VEB / F / Q
(`models/xgboost/xgboost_model.json`, macro-F1 0.7210 on the abnormal
subset). Normal-gated beats skip it entirely, so per-event cost is
dominated by the (very fast) autoencoder.

Feature contributions for the UI come from XGBoost `pred_contribs`
(SHAP-style), sliced to the predicted class for multiclass output.

**Why hybrid:** routing only ~13% of beats to XGBoost keeps end-to-end
latency low while the AE gate handles the normal-beat majority with
high recall — see the honest trade-off in §5 (hybrid SVEB recall drops
vs. XGBoost-only; the gate trades minority-class recall for a 2×
throughput win and a cheaper normal path).

## 5. Offline Experiments (A–E)

Full numbers in `logs/training/experiments/` (rendered on the
dashboard's Model Performance page; generated by
`training/evaluate_models.py`):

| Experiment | Accuracy | Balanced acc. | Macro F1 | SVEB recall | VEB recall | Mean lat. (ms) | Throughput (ev/s) |
|---|---|---|---|---|---|---|---|
| A · XGBoost only (5-class) | 0.9919 | 0.7551 | 0.7562 | 0.940 | 0.980 | 0.0030 | 339 k |
| B · Autoencoder only | 0.9299 | 0.8585 | 0.8290 | — | — | 0.0005 | 2.66 M |
| C · Hybrid AE → XGB (**prod**) | 0.9278 | 0.5710 | 0.5253 | 0.240 | 0.955 | 0.0018 | 569 k |
| D · XGBoost + AE features | 0.9914 | 0.7494 | 0.7532 | 0.938 | 0.979 | 0.0033 | 309 k |
| E · MLP baseline | 0.9383 | 0.7577 | 0.6042 | 0.964 | 0.954 | 0.0003 | 4.09 M |

Notes: latency/throughput measured on batch scoring of held-out data on
the dev machine — indicators of relative cost, not production SLAs. Q
recall is 0 everywhere (15 samples — not learnable). Experiment C's
macro-F1 is computed over all 5 classes with the gate's SVEB misses
counted against it; its stage-2 routing rate is 12.7%.

## 8. Running

- **Demo (recommended for presentations):** `python3 demo/server.py` →
  http://localhost:8000 (details: dashboard/DASHBOARD.md, Option 0)
- **Local dev:** API (`uvicorn api.main:app --reload`) + dashboard
  (`npm run dev` → http://localhost:5173); no broker needed (in-process
  fallback + SQLite)
- **Full stack:** `docker compose up --build` (Kafka, Spark, Postgres,
  API, dashboard)
- **Redis experiment:** `docker compose --profile redis up redis
  redis-worker` + `MESSAGE_BROKER=redis` on the API
- **Tests:** `pytest` · **Retrain:** see training/ scripts

## 9. Known Limitations & Future Work

- Hybrid gate lowers SVEB recall (0.24 vs 0.94 XGBoost-only) — next
  iteration: lower the AE percentile or add a cheap SVEB-boost path.
- Q class (15 samples) is effectively unlearnable.
- Redis Streams path is code-complete but not yet verified E2E.
- The dashboard ECG trace is synthesized from tabular features (the
  dataset has no raw waveforms).
- Notebooks + a root README walk-through are still to be written.
